# Продолжение работы над «ДЦ Навигатором»

Состояние проекта на 3 ноября 2026 года. Этот файл предназначен для разработчика или нового чата с coding-агентом на другом компьютере.

## Репозиторий и приложение

- Репозиторий: https://github.com/nazar987/Step-by-step-diagnostic-navigator
- Основная ветка: `main`. Релиз: `v0.3.0`.
- Windows: Electron, portable EXE для x64. Android: Capacitor, release APK.
- Общий интерфейс: React и JavaScript, сборка Vite. Electron не используется на Android.
- Android application ID: `ru.navigator.dc`, `versionName 0.3.0`, `versionCode 3`.
- Приложение работает локально: сервер, учётная запись и доступ к оборудованию не нужны.
- В базе 8 разделов, 40 узлов, 28 результатов; на SVG-панели 50 индикаторов.

## Быстрый старт на новом компьютере

Установить Git и Node.js 24 LTS. Для GitHub-команд удобен GitHub CLI (`gh auth login`).

```sh
git clone https://github.com/nazar987/Step-by-step-diagnostic-navigator.git
cd Step-by-step-diagnostic-navigator
npm ci
npm run dev
```

Браузер: `http://127.0.0.1:5173/`. Desktop с live reload: `npm run desktop:dev`.
Первый запуск Electron скачивает его бинарник; это не требование к интернету для установленного приложения.

```sh
npm test
npm run build
npx playwright install chromium
npm run test:e2e
node scripts/test-desktop.mjs
```

Playwright использует production-preview на порту 4173; перед ним нужна свежая `npm run build`.
На Linux для Chromium могут понадобиться системные зависимости (`npx playwright install --with-deps chromium`).
Desktop smoke test проверяет загрузку интерфейса и изоляцию renderer в отдельном профиле.

## Согласованные решения интерфейса

- Два основных режима: «Пошаговая диагностика» и «Всё дерево»; отдельно «Памятка и источники».
- Визуальный стиль: светлая рабочая область, тёмно-зелёная навигация, малиновые светодиоды по фотографии, иконки Lucide.
- Мобильная нижняя навигация и отдельное окно панели; desktop показывает панель рядом с вопросом.
- Название экрана — «Диагностика ДЦ». Убрано прежнее «От симптома к причине» по просьбе пользователя.
- Вариант ответа выбирается основной кнопкой. Предпросмотр панели не продвигает маршрут.
- «Показать индикацию» демонстрирует известные состояния; «Найти индикаторы на панели» показывает только расположение.
- Неописанная лампа имеет состояние «Не задано» и прочерк; это не эквивалент «Выключен».
- При смене шага ручная подсветка и предпросмотр сбрасываются. Пресет фотографии отделён от диагностического примера.
- Фото 1 — статический снимок, а не подтверждённый образец нормального режима.
- Уточнение пользователя: «Нормальная» означает, что состояние всех светодиодов соответствует исправному состоянию статива. Конкретные состояния и последовательность мигания пока не описаны. Нельзя самостоятельно придумывать анимацию нормы.
- Ритм мигания условный. Номера ламп, выбранные только как пример, обозначены в пояснениях.
- Таблица описывает возможные причины, а не подтверждённый диагноз. Неоднозначные маркировки сохраняются с примечаниями и ссылками на фото.

## Сборки и выпуск новой версии

### Windows

```sh
npm run desktop:pack
```

Результат: `release/DC-Navigator-<version>-Windows-x64.exe`. Собирать на Windows.
EXE portable, подпись издателя и автообновление пока не настроены.

### Android

Для локальной компиляции нужны JDK 21 и Android SDK 36. На исходном компьютере был только JDK 15: он используется для локальной подписи, но не для Gradle-компиляции Capacitor.

```sh
npm run android:sync
```

Далее из `android/`: `./gradlew assembleRelease lintRelease` (Windows: `gradlew.bat`).
Без параметров подписи Gradle создаёт `app-release-unsigned.apk` — его нельзя публиковать как готовый установочный APK.

Альтернатива — workflow `Build unsigned Android release` в GitHub Actions. Он сам устанавливает SDK, выполняет проверки и сохраняет артефакт `android-unsigned` на 14 дней. Ключи и пароли в CI не передаются.

Скачать артефакт и подписать локально командой из `docs/DEVELOPMENT.md`. Для публикации использовать только итоговый подписанный `DC-Navigator-<version>-Android.apk`.

Перед новым релизом:

1. Обновить версии в `package.json`, `package-lock.json`, `android/app/build.gradle`; увеличить `versionCode`.
2. Выполнить проверки, собрать EXE и APK, проверить `apksigner verify` и содержимое APK.
3. Создать SHA-256 суммы именно конечных файлов.
4. Закоммитить и отправить изменения, создать тег `v<version>` и GitHub Release.
5. Прикрепить EXE, подписанный APK и `SHA256SUMS.txt`; проверить ссылки и суммы загруженных файлов.

## Перенос ключа Android — до выпуска обновлений

Ключ подписи не входит в git, релиз или этот документ. На исходном компьютере он хранится в каталоге проекта `.release-signing/`:

- `android-release.p12` — постоянный ключ, alias `navigator-release`;
- `password.dpapi` — пароль, защищённый Windows для исходной учётной записи;
- `README.txt` — памятка о хранении.

**Для обновления уже установленного приложения нужен тот же ключ.** Создание нового ключа после простого клонирования репозитория приведёт к несовместимой подписи обновления.

До переезда сохраните `.p12` и его пароль в защищённом хранилище. Простого копирования `password.dpapi` недостаточно: на другом компьютере он не расшифруется.
Пароль можно получить только под исходной учётной записью Windows. Следующие команды копируют его в локальный буфер обмена для переноса в менеджер паролей, не печатая в терминал:

```powershell
$protectedPassword = Get-Content .release-signing/password.dpapi -Raw | ConvertTo-SecureString
$credential = [System.Net.NetworkCredential]::new('', $protectedPassword)
$credential.Password | Set-Clipboard
```

После сохранения очистить буфер обмена (`Set-Clipboard -Value ''`). Не вставлять пароль в чат, README, логи или GitHub.

На новом Windows-компьютере скопировать `.p12` в `.release-signing/`, затем сохранить введённый пароль под новой учётной записью:

```powershell
Read-Host 'Пароль существующего ключа Android' -AsSecureString |
  ConvertFrom-SecureString |
  Set-Content .release-signing/password.dpapi -Encoding utf8
```
